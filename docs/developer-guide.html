DocBuilder developer guide

How DocBuilder is built, the template format, and how to call it from Apex and Flow or connect your own e-signature service.

Architecture

One engine serves every entry point: the record button, Flow, Apex and bulk runs.

ClassRole
DocBuilderGlobal API: generate, generateInBackground, Request and Result.
DocBuilderEngineLoads templates, renders, converts to PDF, saves the file and audit records, sends email.
DocBuilderContextBuilds and runs the user-mode query, resolves fields, evaluates rules, sections, calculations and signers, and records the snapshot.
DocBuilderRendererTurns blocks into HTML for Blob.toPdf (CSS 2.1, tables, paged media).
DocBuilderPrepareExpands clause-library categories and applies translations before rendering.
DocBuilderStoreSystem-mode reads and writes of DocBuilder's own records (audit, deliveries, jobs, signature status).
DocBuilderPolicyEmail and bulk permissions and limits.

Template JSON

DocTemplateVersion__c.Body_JSON__c holds the whole template. The designer writes it; you can also create it in code.

{
  "page": {
    "size": "A4 | Letter | Legal",
    "orientation": "portrait | landscape",
    "margin": "narrow | normal | wide",
    "header": { "text": "…", "logoId": "<ContentVersion Id>", "logoWidth": 120 },
    "footer": { "text": "…", "pageNumbers": true },
    "watermark": { "text": "CONFIDENTIAL", "showIf": RULE }
  },
  "blocks": [ BLOCK, … ],
  "calculations": [
    { "name": "Subtotal", "type": "count | sum | avg | min | max", "source": "QuoteLineItems",
      "field": "TotalPrice", "filter": RULE, "format": "currency" },
    { "name": "Net", "type": "formula", "expression": "calc:Subtotal * 0.9" }
  ],
  "conditions": [ { "name": "CityOk", "rule": RULE } ],
  "signers": [
    { "role": "Company", "name": "{{Owner.Name}}", "email": "{{Owner.Email}}" },
    { "role": "Customer", "source": "OpportunityContactRoles",
      "nameField": "Contact.Name", "emailField": "Contact.Email", "filter": RULE }
  ],
  "messages": { "emailSubject": "…", "emailBody": "…", "signSubject": "…", "signMessage": "…" }
}

Blocks

Every block has id, type, and optionally showIf (RULE), elseText, span (width in percent, 10 to 100), beside (true joins the row above) and align (center, right).

typeProperties
headingtext, level 1–3
texttext, rich (true for HTML text)
tablesource, columns [{header, field, align, format}], rowFilter, orderBy, orderDirection, totals [{label, calc, format}], hideWhenEmpty
imagecontentVersionId, width (pixels)
termstitle, items [{id, text, showIf}], clauseCategory
signatureshowDate, showName
pagebreaknone

Rules

RULE = {
  "logic": "AND | OR | 1 AND (2 OR NOT 3)",
  "conditions": [ { "field": "Amount", "op": "gt", "value": "10000" }, … ]
}
op: eq, ne, gt, ge, lt, le, contains, blank, notBlank

A condition's field can be a path on the record, a related record (Account.Industry), or calc:Name. In a table's rowFilter or a calculation's filter, paths are on the row.

Formulas

Grammar: numbers, field paths, calc:Name (defined earlier in the list), + - * /, brackets, comparisons = == != <> < <= > >= (1 when true, 0 when false), and the functions ROUND(x[, places]), ABS, CEILING, FLOOR, MIN(…), MAX(…), IF(test, then, else), AND(…), OR(…), NOT(x). Empty fields count as 0; division by zero gives 0.

Table totals

A table total whose calculation is a count, sum, avg, min or max over the table's own source is computed again over the rows the table shows (after rowFilter, intersected with the calculation's own filter). Formulas and totals over other lists print their document-wide value.

Conditions the designer creates

conditions entries with "auto": true belong to one conditional part of a text. The designer names them PartN and drops them when no text refers to them; the engine treats them like any named condition.

Text syntax

Tokens: {{Path}}, {{Path|format}}, {{calc:Name}}. Sections: {{#if Path}}, {{#if not Path}}, {{#if cond:Name}}, {{else}}, {{/if}}; they nest. A leading object name equal to the template's base object is ignored, so {{Quote.Name}} on a Quote template means {{Name}}.

Apex API

Generate

DocBuilder.Request req = new DocBuilder.Request();
req.templateName = 'Sales Quote';        // or templateId
req.additionalTemplateIds = otherIds;    // optional: combined into one PDF
req.recordId = quoteId;
req.language = 'fr';                     // optional
req.draft = false;
req.saveToRecord = true;                 // attach to the record's Files
req.emailTo = new List<String>{ 'a@example.com' };   // optional; needs DocBuilder_Send_Email
req.emailSubject = null;                 // blank uses the template's wording

DocBuilder.Result res = DocBuilder.generate(req);
// res.success, res.documentId, res.contentVersionId, res.contentDocumentId,
// res.fileName, res.emailStatus, res.errorMessage, res.signers,
// res.signSubject, res.signMessage

A failed run never throws: it returns success = false and still creates a GeneratedDocument__c with the error.

Bulk

Id jobId = DocBuilder.generateInBackground('Sales Quote', recordIds);
// Needs DocBuilder_Bulk_Generate; capped by Max Bulk Records (default 2000).

E-signature

DocBuilderSign.SendRequest send = new DocBuilderSign.SendRequest();
send.templateId = templateId;
send.recordId = opportunityId;
send.providerName = 'DropboxSign';
send.signers = null;    // optional override, same order as the template's signers
send.subject = null;    // blank uses the template's wording
Id requestId = DocBuilderSign.send(send);

DocBuilderSign.refresh(requestId);           // check status now
DocBuilderSign.cancel(requestId, 'Reason');  // withdraw
String msg = DocBuilderSign.testConnection('DropboxSign');

Custom e-signature providers

Implement DocBuilderSignProvider, then add a DocSignProvider__mdt row naming the class and a Named Credential. Nothing else changes.

global with sharing class AcmeSignProvider implements DocBuilderSignProvider, DocBuilderSignCheck {
    // Text the service looks for to place a field. fieldType: signature, date, name, initials.
    global String marker(Integer signerNumber, String fieldType) {
        return '[[' + fieldType + '_' + signerNumber + ']]';
    }
    global DocBuilderSign.SendResult send(DocBuilderSign.Envelope envelope) {
        Map<String, Object> payload = new Map<String, Object>{
            'title' => envelope.subject,
            'file' => EncodingUtil.base64Encode(envelope.file),
            'signers' => envelope.signers
        };
        HttpResponse response = DocBuilderSignHttp.callJson(envelope.config, 'POST', '/v1/requests', payload);
        DocBuilderSign.SendResult result = new DocBuilderSign.SendResult();
        result.externalId = (String) DocBuilderSignHttp.parse(response).get('id');
        return result;
    }
    global DocBuilderSign.StatusResult getStatus(DocBuilderSign.ProviderConfig config, String externalId) {
        Map<String, Object> answer = DocBuilderSignHttp.parse(
            DocBuilderSignHttp.call(config, 'GET', '/v1/requests/' + DocBuilderSignHttp.pathId(externalId), null, null));
        DocBuilderSign.StatusResult result = new DocBuilderSign.StatusResult();
        result.status = answer.get('state') == 'done' ? 'Completed' : 'Sent';  // Sent, Completed, Declined, Voided
        return result;
    }
    global Blob download(DocBuilderSign.ProviderConfig config, String externalId) {
        return DocBuilderSignHttp.call(config, 'GET', '/v1/requests/' + DocBuilderSignHttp.pathId(externalId) + '/file', null, null).getBodyAsBlob();
    }
    global void cancel(DocBuilderSign.ProviderConfig config, String externalId, String reason) {
        DocBuilderSignHttp.call(config, 'DELETE', '/v1/requests/' + DocBuilderSignHttp.pathId(externalId), null, null);
    }
    global String check(DocBuilderSign.ProviderConfig config) {
        DocBuilderSignHttp.call(config, 'GET', '/v1/me', null, null);
        return 'Connected to Acme Sign.';
    }
}
  • config.settings is the row's Settings JSON, parsed.
  • DocBuilderSignHttp calls through the Named Credential and throws ProviderException on any non-2xx answer: a user-safe message, with the service's response in detail for admins.
  • Always pass references through DocBuilderSignHttp.pathId before putting them in a URL.
  • getStatus may report each signer in result.signers; if not, all are marked Signed on completion. download may return null to keep the sent copy.
  • Optional interfaces: DocBuilderSignWebhook (instant notifications) and DocBuilderSignCheck (Test connection).
  • Setting the row's Custom Screen Flow replaces the signing screen. The flow receives recordId, templateId and providerName, and can use the Send Document for Signature action.

Notifications

/services/apexrest/docbuilder/sign/<ProviderName>?token=<secret> runs as the Site guest user. It checks the secret from DocSignSecret__c with a timing-safe comparison, asks the provider's DocBuilderSignWebhook.externalIdOf which request changed, and publishes DocSignNotice__e. Every rejection returns the same empty 401. The trigger DocSignNoticeTrigger runs outside the guest context and queues DocBuilderSignSyncJob, which fetches the real status from the provider. Nothing in a notification changes a record directly.

To give the handler access to provider credentials, create a PlatformEventSubscriberConfig for DocSignNoticeTrigger with an integration user.

Security design

  • Record data is read with AccessLevel.USER_MODE; all user-facing queries use WITH USER_MODE and DML uses as user.
  • DocBuilder's own records are written in system mode only through DocBuilderStore, so users get read-only access and cannot forge the audit trail.
  • Dynamic SOQL uses only paths matching a strict identifier pattern, with bind variables.
  • Rich text is cleaned server-side with a tag and attribute allowlist; previews are cleaned again in the browser.
  • Email and bulk are gated by custom permissions (DocBuilder_Send_Email, DocBuilder_Bulk_Generate) and limits.
  • Unexpected errors show a generic message; detail goes to admin-only Error_Detail__c.

Testing and deployment

  • Test classes: DocBuilderTest, DocBuilderDesignerTest, DocBuilderSignTest, DocBuilderSecurityTest; helpers in DocBuilderTestUtil.
  • The TestProvider row and DocBuilderSignMock exercise signing without a service. In tests, DocBuilderSign.testSettings supplies provider settings and a Unit_Credential Named Credential name for callout mocks.
  • Blob.toPdf is unavailable in tests, so tests store the HTML instead.
sf project deploy start --source-dir force-app --target-org <alias> \
  --test-level RunSpecifiedTests --tests DocBuilderTest --tests DocBuilderDesignerTest \
  --tests DocBuilderSignTest --tests DocBuilderSecurityTest
Changing an object's sharing setting and testing it in the same deploy does not work: sharing is recalculated after the deploy. Deploy objects and permission sets first, wait for the recalculation, then deploy code with tests.

force-app is the package. org-setup holds org-specific items (the Quote action, the Dropbox Sign credential and its access permission set) and is not part of the package.

Limits

  • 500 rows per related list per document.
  • Snapshots are capped at about 130,000 characters; row data is dropped first if larger.
  • 50 signers per request.
  • Status checks handle 10 requests per run; notifications start at most 5 checks of 10 requests per batch.
  • PDF layout is limited to what Salesforce's PDF engine supports: CSS 2.1, tables, no flexbox.
