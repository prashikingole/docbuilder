DocBuilder developer guide

How DocBuilder is built, the template format, and how to call it from Apex and Flow or connect your own e-signature service.

Architecture

One engine serves every entry point: the record button, Flow, Apex and bulk runs.

Template JSON

DocTemplateVersion__c.Body_JSON__c holds the whole template. The designer writes it; you can also create it in code.

{
  "page": {
    "size": "A4 | Letter | Legal",
    "orientation": "portrait | landscape",
    "margin": "narrow | normal | wide",
    "header": { "text": "…", "logoId": "<ContentVersion Id>", "logoWidth": 120 },
    "footer": { "text": "…", "pageNumbers": true },
    "watermark": { "text": "CONFIDENTIAL", "showIf": RULE,
                   "direction": "across | diagonal", "size": "fit | large | medium | small",
                   "shade": "light | medium | dark",
                   "imageId": "<ContentVersion Id>", "draftImageId": "…", "imageKey": "…" }
  },
  "blocks": [ BLOCK, … ],
  "dataSources": [ DATA SOURCE, … ],      // see Data sources and extensions
  "apexChecks": [ APEX VARIABLE, … ],     // see Data sources and extensions
  "calculations": [
    { "name": "Subtotal", "type": "count | sum | avg | min | max", "source": "QuoteLineItems",
      "field": "TotalPrice", "filter": RULE, "format": "currency" },
    { "name": "Net", "type": "formula", "expression": "calc:Subtotal * 0.9" }
  ],
  "conditions": [ { "name": "CityOk", "rule": RULE } ],
  "signers": [
    { "role": "Company", "name": "{{Owner.Name}}", "email": "{{Owner.Email}}" },
    { "role": "Customer", "source": "OpportunityContactRoles",
      "nameField": "Contact.Name", "emailField": "Contact.Email", "filter": RULE }
  ],
  "messages": { "emailSubject": "…", "emailBody": "…", "signSubject": "…", "signMessage": "…" }
}

Diagonal watermarks: the PDF engine can't rotate text, so the designer draws the text (and DRAFT) at 45° into PNGs when the template is saved. It stores their ContentVersion Ids in imageId and draftImageId, with imageKey recording the text and shade they were drawn from. A diagonal watermark whose text has fields prints across the page.

Blocks

Every block has id, type, and optionally showIf (RULE), elseText, span (width in percent, 10 to 100), beside (true joins the row above) and align (center, right).

typeProperties
headingtext, level 1–3
texttext, rich (true for HTML text)
tablesource (a relationship, Account.Contacts, or ds:Name), groupBy (a field of the row; adds a tr.grp heading per group), groupTotals (true repeats the summary rows per group as tr.tot.sub), columns [{header, field, align, format, show, showIf}] (show: always (default), filled (printed only when some shown row is not blank or zero), or rule (printed only when the RULE in showIf passes on the record)), rowFilter, orderBy, orderDirection, totals [{label, calc, format}], hideWhenEmpty
imagecontentVersionId, width (pixels)
termstitle, items [{id, text, showIf}], clauseCategory
signatureshowDate, showName
pagebreaknone
customsource (apex or visualforce), className and settings (Apex), or page (Visualforce page name, opened with ?id= the record). The output passes through DocBuilderRenderer.cleanCode, which removes scripts, frames, forms, event attributes and script URLs.

Rules

RULE = {
  "logic": "AND | OR | 1 AND (2 OR NOT 3)",
  "conditions": [ { "field": "Amount", "op": "gt", "value": "10000" }, … ]
}
op: eq, ne, gt, ge, lt, le, contains, blank, notBlank

A condition's field can be:

  • a path on the record, or on a related record (Account.Industry);
  • calc:Name;
  • ds:Name.Field, which reads the first row of a data source;
  • apex:Name, an Apex variable.

Values compare by type: numbers numerically, dates as dates (YYYY-MM-DD), and text case-insensitively. In a table's rowFilter or a calculation's filter, paths are on the row.

Formulas

Grammar: numbers, field paths, calc:Name (defined earlier in the list), + - * /, brackets, comparisons = == != <> < <= > >= (1 when true, 0 when false), and the functions ROUND(x[, places]), ABS, CEILING, FLOOR, MIN(…), MAX(…), IF(test, then, else), AND(…), OR(…), NOT(x). Empty fields count as 0; division by zero gives 0.

Table totals

A table total whose calculation is a count, sum, avg, min or max over the table's own source is computed again over the rows the table shows (after rowFilter, intersected with the calculation's own filter). Formulas and totals over other lists print their document-wide value.

Conditions the designer creates

conditions entries with "auto": true belong to one conditional part of a text. The designer names them PartN and drops them when no text refers to them; the engine treats them like any named condition.

Text syntax

Tokens: {{Path}}, {{Path|format}}, {{calc:Name}}, {{ds:Name.Field}} (the data source's first row) and {{apex:Name}} (yes/no prints Yes/No). Sections: {{#if Path}}, {{#if not Path}}, {{#if cond:Name}}, {{#if ds:Name.Field}}, {{#if apex:Name}} (true for yes, a non-zero number or non-empty text), {{else}}, {{/if}}; they nest. A leading object name equal to the template's base object is ignored, so {{Quote.Name}} on a Quote template means {{Name}}.

Apex API

Generate

DocBuilder.Request req = new DocBuilder.Request();
req.templateName = 'Sales Quote';        // or templateId
req.additionalTemplateIds = otherIds;    // optional: combined into one PDF
req.recordId = quoteId;
req.language = 'fr';                     // optional
req.draft = false;
req.saveToRecord = true;                 // attach to the record's Files
req.emailTo = new List<String>{ 'a@example.com' };   // optional; needs DocBuilder_Send_Email
req.emailSubject = null;                 // blank uses the template's wording

DocBuilder.Result res = DocBuilder.generate(req);
// res.success, res.documentId, res.contentVersionId, res.contentDocumentId,
// res.fileName, res.emailStatus, res.errorMessage, res.signers,
// res.signSubject, res.signMessage

A failed run never throws: it returns success = false and still creates a GeneratedDocument__c with the error.

Bulk

Id jobId = DocBuilder.generateInBackground('Sales Quote', recordIds);
// Needs DocBuilder_Bulk_Generate; capped by Max Bulk Records (default 2000).

E-signature

DocBuilderSign.SendRequest send = new DocBuilderSign.SendRequest();
send.templateId = templateId;
send.recordId = opportunityId;
send.providerName = 'DropboxSign';
send.signers = null;    // optional override, same order as the template's signers
send.subject = null;    // blank uses the template's wording
Id requestId = DocBuilderSign.send(send);

DocBuilderSign.refresh(requestId);           // check status now
DocBuilderSign.cancel(requestId, 'Reason');  // withdraw
String msg = DocBuilderSign.testConnection('DropboxSign');

Data sources and extensions

Three ways to go beyond the record and its lists: data sources (extra queries built from pick-lists, no code), Apex variables (values from code, used in rules and text) and Custom content blocks (HTML from Apex or a Visualforce page).

Data sources in the template JSON

"dataSources": [
  {
    "name": "Contracts",                 // used as ds:Contracts; letters, digits, underscores
    "object": "Contract",
    "match": "all",                      // all | any
    "filters": [
      { "field": "AccountId", "op": "eq", "from": "record", "recordField": "AccountId" },
      { "field": "Status", "op": "eq", "from": "value", "value": "Activated" },
      { "field": "Id", "op": "in", "from": "list", "list": "ds:Other", "listField": "ContractId" }
    ],
    "orderBy": "StartDate", "orderDirection": "DESC", "limit": 50
  }
]
  • op: eq, ne, gt, ge, lt, le, contains, blank, notBlank, and for from: "list" in or notIn. A typed value is converted to the field's type (dates as YYYY-MM-DD).
  • Every value is a bind variable in a USER_MODE query. The object, fields and sort field are checked against the schema and the safe-name pattern.
  • A source is a list keyed ds:Name wherever lists are used: table source, calculation source, signer source. {{ds:Name.Field}} (and {{#if ds:Name.Field}}, and rule fields) read its first row.
  • Sources load in order after the record and its lists, so a filter can use lists and earlier sources. Unused sources aren't queried. Maximum 10 per template, 500 rows each. Rows appear in the audit snapshot under ds:Name.

Apex content for a Custom block

global with sharing class AcmeWarrantyTable implements DocBuilderContentProvider {
    global String render(DocBuilderContentRequest request) {
        // request.recordId, request.objectName, request.settings (the block's Settings text), request.language
        List<Asset> assets = [SELECT Name, UsageEndDate FROM Asset
                              WHERE AccountId IN (SELECT AccountId FROM Opportunity WHERE Id = :request.recordId)
                              WITH USER_MODE];
        String html = '<table class="t"><tr><th>Asset</th><th>Warranty ends</th></tr>';
        for (Asset a : assets) {
            html += '<tr><td>' + a.Name.escapeHtml4() + '</td><td>' + a.UsageEndDate + '</td></tr>';
        }
        return html + '</table>';
    }
}
  • Return HTML the PDF engine supports (CSS 2.1; the document's table.t style is available). Escape every data value.
  • The class runs as the user generating the document, once per document (bulk included). Use with sharing and USER_MODE.
  • Exceptions stop generation with the message "The Apex class … failed: …".

Apex variables (many values from one class)

global with sharing class AccountFacts implements DocBuilderVariableProvider {
    global Map<String, String> describeVariables() {          // name -> Boolean | Number | Text | Date
        return new Map<String, String>{ 'OpenCaseCount' => 'Number', 'HasOpenCases' => 'Boolean', 'Tier' => 'Text' };
    }
    global Map<String, Object> getValues(DocBuilderContentRequest request) {
        Integer open = [SELECT COUNT() FROM Case WHERE AccountId IN
                        (SELECT AccountId FROM Opportunity WHERE Id = :request.recordId)
                        AND IsClosed = false WITH USER_MODE];
        return new Map<String, Object>{ 'OpenCaseCount' => open, 'HasOpenCases' => open > 0, 'Tier' => 'Gold' };
    }
}

The template registers one entry per value it uses: "apexChecks": [{ "name": "OpenCases", "className": "AccountFacts", "variable": "OpenCaseCount", "type": "Number", "settings": "" }].

  • getValues runs once per class and settings text per document; names are matched case-insensitively.
  • Values compare by type in rules (numbers numerically, dates as dates) and print with the document's number and date formats. Yes/no prints as Yes/No.
  • Adding a value only means adding it to both maps.
  • DocBuilderDesignerController.describeApexClass lists the values for the designer, and Check fields reports a variable that names a value the class doesn't offer.

Single yes/no classes (earlier interface, still supported)

A class implementing DocBuilderConditionProvider answers one yes/no. Prefer DocBuilderVariableProvider for new work: one class can then serve any number of values.

global with sharing class HasOpenCases implements DocBuilderConditionProvider {
    global Boolean evaluate(DocBuilderContentRequest request) {
        // request.recordId, objectName, settings (the check's Settings text), language
        return [SELECT COUNT() FROM Case WHERE AccountId IN
                (SELECT AccountId FROM Opportunity WHERE Id = :request.recordId)
                AND IsClosed = false WITH USER_MODE] > 0;
    }
}

The check is registered in the template JSON as "apexChecks": [{ "name": "OpenCases", "className": "HasOpenCases", "settings": "" }].

  • In rules it's referenced as the condition field apex:OpenCases, with op eq and value true or false.
  • In text it's {{#if apex:OpenCases}}.
  • It's evaluated lazily, once per document, and the result is recorded in the snapshot's rule log.
  • Check fields verifies names, classes and that every apex:Name used is defined.
  • An exception in either kind of class stops generation with "The Apex variable … failed: …".

Visualforce content

PageReference.getContent() is called for /apex/Page?id=recordId, and only the page's <body> is kept. Salesforce treats this like a callout:

  • It's not possible after uncommitted DML in the same transaction. DocBuilder renders before it saves.
  • It's not available in Apex tests, where the block prints a placeholder.

LWC and Aura can't be rendered server-side, so they can't be included in PDFs.

Custom e-signature providers

Implement DocBuilderSignProvider, then add a DocSignProvider__mdt row naming the class and a Named Credential. Nothing else changes.

global with sharing class AcmeSignProvider implements DocBuilderSignProvider, DocBuilderSignCheck {
    // Text the service looks for to place a field. fieldType: signature, date, name, initials.
    global String marker(Integer signerNumber, String fieldType) {
        return '[[' + fieldType + '_' + signerNumber + ']]';
    }
    global DocBuilderSign.SendResult send(DocBuilderSign.Envelope envelope) {
        Map<String, Object> payload = new Map<String, Object>{
            'title' => envelope.subject,
            'file' => EncodingUtil.base64Encode(envelope.file),
            'signers' => envelope.signers
        };
        HttpResponse response = DocBuilderSignHttp.callJson(envelope.config, 'POST', '/v1/requests', payload);
        DocBuilderSign.SendResult result = new DocBuilderSign.SendResult();
        result.externalId = (String) DocBuilderSignHttp.parse(response).get('id');
        return result;
    }
    global DocBuilderSign.StatusResult getStatus(DocBuilderSign.ProviderConfig config, String externalId) {
        Map<String, Object> answer = DocBuilderSignHttp.parse(
            DocBuilderSignHttp.call(config, 'GET', '/v1/requests/' + DocBuilderSignHttp.pathId(externalId), null, null));
        DocBuilderSign.StatusResult result = new DocBuilderSign.StatusResult();
        result.status = answer.get('state') == 'done' ? 'Completed' : 'Sent';  // Sent, Completed, Declined, Voided
        return result;
    }
    global Blob download(DocBuilderSign.ProviderConfig config, String externalId) {
        return DocBuilderSignHttp.call(config, 'GET', '/v1/requests/' + DocBuilderSignHttp.pathId(externalId) + '/file', null, null).getBodyAsBlob();
    }
    global void cancel(DocBuilderSign.ProviderConfig config, String externalId, String reason) {
        DocBuilderSignHttp.call(config, 'DELETE', '/v1/requests/' + DocBuilderSignHttp.pathId(externalId), null, null);
    }
    global String check(DocBuilderSign.ProviderConfig config) {
        DocBuilderSignHttp.call(config, 'GET', '/v1/me', null, null);
        return 'Connected to Acme Sign.';
    }
}
  • config.settings is the row's Settings JSON, parsed.
  • DocBuilderSignHttp calls through the Named Credential and throws ProviderException on any non-2xx answer: a user-safe message, with the service's response in detail for admins.
  • Always pass references through DocBuilderSignHttp.pathId before putting them in a URL.
  • getStatus may report each signer in result.signers; if not, all are marked Signed on completion. download may return null to keep the sent copy.
  • Optional interfaces: DocBuilderSignWebhook (instant notifications) and DocBuilderSignCheck (Test connection).
  • Setting the row's Custom Screen Flow replaces the signing screen. The flow receives recordId, templateId and providerName, and can use the Send Document for Signature action.

Notifications

/services/apexrest/docbuilder/sign/<ProviderName>?token=<secret> runs as the Site guest user. It checks the secret from DocSignSecret__c with a timing-safe comparison, asks the provider's DocBuilderSignWebhook.externalIdOf which request changed, and publishes DocSignNotice__e. Every rejection returns the same empty 401. The trigger DocSignNoticeTrigger runs outside the guest context and queues DocBuilderSignSyncJob, which fetches the real status from the provider. Nothing in a notification changes a record directly.

To give the handler access to provider credentials, create a PlatformEventSubscriberConfig for DocSignNoticeTrigger with an integration user.

The Import wizard, with three sources: a file or pasted text, a template in this org, or the standard quote layout. Its browser-side reader handles .docx (unzipped with DecompressionStream), HTML, text and DocBuilder exports.

Each recognised tag becomes a token kind:

  • field: merge fields in every supported style, including DocuSign Gen Content tags, whose XPath becomes a field path.
  • listStart / listEnd: TableStart, Gen TableRow, {{#list}}.
  • ifStart / else / ifEnd: {{#if X}}, {{^X}}. A comparison is flagged complex.
  • control: other Gen tags.

Word IF fields are counted, and fields nested inside another field's instruction are ignored. balanceSections keeps every text block's conditions paired before saving.

docBuilderSafeHtmlRenders previews by parsing and allow-listing nodes; no innerHTML.

Security design

  • Record data is read with AccessLevel.USER_MODE; all user-facing queries use WITH USER_MODE and DML uses as user.
  • DocBuilder's own records are written in system mode only through DocBuilderStore, so users get read-only access and cannot forge the audit trail.
  • Dynamic SOQL uses only paths matching a strict identifier pattern, with bind variables.
  • Rich text is cleaned server-side with a tag and attribute allowlist; previews are cleaned again in the browser.
  • Email and bulk are gated by custom permissions (DocBuilder_Send_Email, DocBuilder_Bulk_Generate) and limits.
  • Unexpected errors show a generic message; detail goes to admin-only Error_Detail__c.
  • Data sources only use objects, fields and operators checked against the schema; every compared value is a bind variable in a USER_MODE query.
  • HTML from Custom content (Apex or Visualforce) passes through DocBuilderRenderer.cleanCode, which removes scripts, frames, forms, event attributes and script URLs. Previews are cleaned again in the browser.
  • Apex variable, content and Visualforce classes run as the user generating the document. Only admins, who have the designer, can choose them.
  • New signature requests are refused for providers that aren't switched on. Requests already sent keep updating.
  • saveWatermarkImage accepts only PNG data and attaches it to a template the user can see.

Testing and deployment

  • Test classes: DocBuilderTest, DocBuilderDesignerTest, DocBuilderSignTest, DocBuilderSecurityTest, DocBuilderInstallTest, DocBuilderImportTest, DocBuilderSourcesTest (data sources, Custom content, Apex variables, grouping); helpers in DocBuilderTestUtil. The samples have DocBuilderSampleContentTest.
  • The TestProvider row and DocBuilderSignMock exercise signing without a service. In tests the Test provider always counts as switched on (an org may have turned it off), and DocBuilderSign.testInactive switches providers off. DocBuilderSign.testSettings supplies provider settings and a Unit_Credential Named Credential name for callout mocks.
  • Blob.toPdf and PageReference.getContent() are unavailable in tests. Tests store the HTML instead, and Visualforce blocks print a placeholder.
  • AuraHandledException hides its message in tests unless it is set with setMessage; the designer controller's newer methods do this (userError) so tests can check the text.
sf project deploy start --source-dir force-app --target-org <alias> \
  --test-level RunSpecifiedTests --tests DocBuilderTest --tests DocBuilderDesignerTest \
  --tests DocBuilderSignTest --tests DocBuilderSecurityTest --tests DocBuilderInstallTest \
  --tests DocBuilderImportTest --tests DocBuilderSourcesTest
Changing an object's sharing setting and testing it in the same deploy does not work: sharing is recalculated after the deploy. Deploy objects and permission sets first, wait for the recalculation, then deploy code with tests.

The project has three folders:

  • force-app is the package, including the Dropbox Sign credential shells, the permission sets and groups, and the post-install script.
  • org-setup holds org-specific items (the Quote action).
  • samples holds the extension examples.

Neither org-setup nor samples is part of the package.

Coverage at the last full run (November 2026): 55 tests, 94% overall, every class with code at 85% or more.

Limits

  • 500 rows per related list per document.
  • 10 data sources per template, 500 rows each (200 unless set); only sources the template uses are queried.
  • Formulas and rule logic may nest up to 40 levels.
  • Template body up to 131,072 characters, which also applies to imports.
  • Each Apex variable class runs once per document per settings text, inside the same governor limits as the rest of the generation.
  • Snapshots are capped at about 130,000 characters; row data is dropped first if larger.
  • 50 signers per request.
  • Status checks handle 10 requests per run; notifications start at most 5 checks of 10 requests per batch.
  • PDF layout is limited to what Salesforce's PDF engine supports: CSS 2.1, tables, no flexbox.
