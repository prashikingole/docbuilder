DocBuilder admin guide

Setting up DocBuilder: who can use it, where the button appears, how to design templates, and how to connect an e-signature service.

Give people access

Give each person one group in Setup › Users › Permission Set Groups. A group includes the permission sets below, so you don't assign them one by one.

Permission set groupIncludesFor
DocBuilder AdminsDocBuilder Admin, DocBuilder E-Signature AccessPeople who build templates and look after DocBuilder. Admins can already email documents and run bulk generation.
DocBuilder UsersDocBuilder User, DocBuilder E-Signature AccessPeople who generate documents and send them for signature.

Emailing documents and bulk generation are deliberately not in DocBuilder Users. Give DocBuilder Email Sender or DocBuilder Bulk Runner on top of the group only to the users who need them.

The permission sets inside the groups:

Permission setGives
DocBuilder AdminThe Template Designer; create and edit templates, clauses and translations; see every generated document, signature request and bulk job; email documents; run bulk generation.
DocBuilder UserGenerate documents and send them for signature from active templates. Users see only their own generated documents and signature requests.
DocBuilder Email SenderAdd to DocBuilder User to allow emailing documents.
DocBuilder Bulk RunnerAdd to DocBuilder User to allow bulk generation.
DocBuilder E-Signature AccessLets the user's documents be sent through the e-signature credentials that come with DocBuilder (currently Dropbox Sign). Already in both groups. For credentials you create yourself, such as DocuSign or Adobe Acrobat Sign, create a permission set giving access to that credential's principal and assign it as well.

The DocBuilder app has these tabs: Template Designer, Document Templates, Document Clauses, Generated Documents, Signature Requests and Document Bulk Jobs.

Generated documents, signature requests and bulk jobs are private: users see their own. Templates, clauses and translations are read-only for users. Generated records can't be edited or deleted by anyone through the UI, so the audit trail stays intact.

Add the Generate Document button

Opportunity comes with a Generate Document action. For any other object:

  1. Go to Setup › Object Manager › [object] › Buttons, Links, and Actions › New Action.
  2. Action Type: Lightning Web Component. Lightning Web Component: c:docBuilderGenerateAction (shown as "DocBuilder Generate Document (large dialog)").
  3. Label: Generate Document. Save.
  4. Add it to the page: in the page layout under Mobile & Lightning Actions, or as a Dynamic Action in the Lightning App Builder.

The button opens a large dialog with the options on the left and a live preview on the right.

To show where documents land, add the Files related list to the object's page layout.

Create a template

  1. Open Template Designer and click New.
  2. Enter a name and the object it's built on, by API name, for example Quote, Opportunity or My_Object__c.
  3. Add blocks from the rail on the left: Text, Heading, Table, Image, Terms, Sign and Break (a page break).
  4. Click a block to edit it in Settings on the right. Use the arrows to move it and the bin to delete it.
  5. Use the bar under the page for page setup, header and footer, conditions, signers, email wording, calculated values, and the template's name and languages.
  6. Click Save draft, then Activate when it's ready.

Fields and text

Open the Fields tab and click a field to add it to the selected text. The list is read live from your org. Open Related records to reach fields on records this one points to, such as Account or Owner. Click a list under Lists, added as tables to add a table.

Fields are stored as tokens you can also type:

TokenPrints
{{Name}}A field on the record.
{{Account.Name}}A field on a related record.
{{calc:Subtotal}}A calculated value (see Tables and totals).
{{Amount|currency}}A field with a format: currency, number, percent, date, upper or lower.

Tick Rich text on a text block for bold, colours, sizes, lists and alignment. Links, images and scripts are removed from rich text for security.

Conditions

Show a whole block only if…

Every block has Visibility: show this block only if. Add numbered conditions (field, operator, value) and choose how to combine them: leave blank or type AND for all, OR for any, or custom logic such as 1 AND (2 OR NOT 3). Text blocks can show Otherwise show this text instead.

Operators: equals, does not equal, is greater than, is at least, is less than, is at most, contains, is blank, is not blank. Pick the field from the list: the record's own fields, Calculated: … values, or a related record (for example Account ›, then Industry in the second list). The value box matches the field: a list for picklists, Yes/No for checkboxes, a date picker for dates.

Show part of a text only if…

  1. Click a field on the page (it is outlined when you point at it).
  2. In Settings, click Show only if…. The field, the comma or space after it and, when it is alone on its line, the line break become one conditional part. It turns green and gets a number.
  3. It starts as "has a value". Add conditions to change that, for example City is not Delhi.

A key under the block lists each numbered part and when it prints, in plain words. Click a part or its line in the key to change its text, its rule, or the text printed otherwise, or to make it always print again. Before inserting address lines, set When you insert a field to Print it only when it has a value to make each one conditional as you add it.

Behind the scenes these are stored as text, which you can also type:

WritePrints the inside
{{#if City}} … {{/if}}when City has a value
{{#if not City}} … {{/if}}when City is empty
{{#if cond:CityOk}} … {{/if}}when the named condition CityOk is true
… {{else}} …the alternative, inside any of the above

A part with more than a "has a value" check gets its own condition automatically, named Part1, Part2 and so on. It is removed when no text uses it. Use the Conditions panel in the bar under the page only for a rule shared by several texts.

Tables and totals

  • Rows come from: a list on this record (Quote Line Items, Opportunity Products), or a list on a related record, typed as Account.Contacts.
  • Columns: heading, field, alignment and format. Click fields in the Fields tab to add columns.
  • Which rows to include: a rule applied to each row.
  • Sorting: any field, ascending or descending.
  • Summary rows: a label and a calculated value under the table. A count, sum, average, lowest or highest over the table's own list adds up only the rows the table shows, after its row filter. Totals of money or percentages print in the field's format unless you choose another.
  • Add a total for these rows: creates a calculated value over the same list and a summary row showing it.
  • Hide the table when there are no rows.

The same list can feed several tables, each with its own filter, sort and totals; for example, products split into hardware and services.

Calculated values

Under Calculated values: count, sum, average, lowest or highest over a list, with an optional row filter; or a formula.

In the formula bar, start typing a field's name or label and pick it from the suggestions. Related records open with ›, for example Account › Annual Revenue. Under the bar, the formula is read back with field labels; anything that isn't a field or function is marked red with the reason. Pick a record in Try them with this record to see each value worked out as you type.

Layout and page

  • Side by side: drag a block by its label onto the left or right edge of another block; a blue bar shows where it will land. Up to four blocks fit in a row and share the width equally. Drag the line between two blocks to change their widths; it snaps to 5% steps and to thirds. Drop a block above or below a row to make it full width again. Without a mouse: select a block and use Width and Place beside the block above under Layout, or focus a dividing line and press ← or →.
  • Page setup: A4, US Letter or US Legal; portrait or landscape; narrow, normal or wide margins.
  • Header: a logo and text repeated on every page. Footer: text and optional "Page 1 of 3".
  • Watermark: light grey text in the middle of every page, behind the content, optionally only when a rule is met. Its size is set automatically to fit the page width, so short words print large and longer phrases print smaller. A document generated as a draft shows DRAFT instead of this watermark.
  • Images: upload in the Image block's settings and set its width and alignment.
PDFs are produced by Salesforce's PDF engine, which supports simple layouts. Keep designs to headings, text, tables, images and columns.

Terms and the clause library

A Terms block prints a numbered list of clauses. Each clause can have its own rule; numbering closes up when a clause is left out.

Shared clauses live on the Document Clauses tab: Name, Category, Text (fields allowed), Sort Order, Active, Locked Wording, and Rule JSON. A Terms block that names a category in Also include library clauses in category prints every active clause in that category, so one change updates every template.

Signers

Open Signers in the bar under the page, add signers in signing order, and add a Sign block where they sign. For each signer choose Who signs:

  • A person on this record: pick a user, contact or lead lookup, such as Owner or Contact.
  • Everyone in a related list: for example every Opportunity Contact Role, with an optional filter such as Role equals Decision Maker. People without an email address are left out. Up to 50 people.
  • Typed in or from fields: type a name and email, or field tokens.

The Sign block prints one signing area per person, three to a row, with optional date and printed name. Without e-signature, these are lines to sign by hand.

Email and signing wording

Under Emails in the bar under the page, set the subject and message used when this document is emailed, and when it is sent for signature. Fields and conditions work here too. They prefill the Generate Document dialog, where senders can still change them.

Languages

  1. Under Name and languages, list language codes, for example en, fr, de.
  2. Switch to Translate, choose a language, and translate each piece of text. Keep the field tokens exactly as they are; you can move them within the sentence.
  3. Text left blank prints in the default language. If the original text changes later, its translation is flagged as out of date.

Field labels and picklist values come from Salesforce's Translation Workbench, not from DocBuilder.

Preview, check and activate

  • Preview: pick any record to see exactly what it would produce. Uses your unsaved changes and saves nothing.
  • Check fields (in the bar under the page): confirms every field the template uses exists and is readable.
  • Save draft: saves without affecting users. Editing an active template creates a new draft version.
  • Activate: makes the draft live. The previous version is archived, never deleted. Users always generate from the active version.

Set up e-signature

Each service is a row in Setup › Custom Metadata Types › Signature Provider › Manage Records: Label, Apex Class, Named Credential, Button Label, Sort Order, Screen Style (form, steps or desk), Custom Screen Flow, Settings JSON and Active. Only active providers are offered to users. The Test provider sends nothing and reports everyone as signed; deactivate it before going live.

Test any provider, active or not, with Test connection under Signers in the Template Designer.

Where settings and secrets are kept. Each store holds something different:

  • Signature Provider (custom metadata): which services are on and how they behave. No secrets.
  • External Credential: the API key or sign-in for each service, encrypted by Salesforce.
  • Signature Webhook Secret (custom setting): only the password that the service sends back to Salesforce with each instant update. It is a separate value you make up; it is not the API key.

Dropbox Sign

  1. In Dropbox Sign, open Settings › API and copy your API key. A free account works in test mode.
  2. In Salesforce: Setup › Named Credentials › External Credentials › DocBuilder_DropboxSign. The package installs this, its principal DropboxSignKey, and the Named Credential DocBuilder_DropboxSign; only your key is missing.
  3. Under Principals, edit DropboxSignKey. Under Authentication Parameters, add Name ApiKey with your key as the Value. The name must be exactly ApiKey. Salesforce encrypts the key; nobody can read it back, including DocBuilder's code.
  4. Check that everyone who will send has the DocBuilder Users or DocBuilder Admins group. Both include DocBuilder E-Signature Access, which gives access to this credential.
  5. Run Test connection. It should say "Connected to Dropbox Sign as …".
  6. On the Dropbox Sign provider row, set Settings JSON to {"testMode":true} while testing, and tick Active. Remove testMode once you have a paid API plan; test requests are free but not legally binding.

DocuSign

  1. Create an integration (app) in DocuSign and an OAuth External Credential and Named Credential in Salesforce, named DocBuilder_DocuSign, pointing at your account's base URL, for example https://demo.docusign.net.
  2. Set the provider's Settings JSON to {"accountId":"<your API account ID>"}.
  3. Give senders access to the credential's principal, test the connection, and activate.

Adobe Acrobat Sign

  1. Create a Named Credential DocBuilder_AdobeSign pointing at your regional API address, for example https://api.na1.adobesign.com, signed in with OAuth or an integration key.
  2. Give senders access, test the connection, and activate.

Other services

A developer can connect any service with one Apex class; see the developer guide. You can also replace the signing screen for a provider with your own screen flow, named in Custom Screen Flow.

Signature status updates

Every 15 minutes: the package starts this check when it is installed or upgraded. You can see it in Setup › Scheduled Jobs as DocBuilder signature status :00, :15, :30 and :45. If those jobs are missing, start them from the Developer Console's Anonymous Apex window:

DocBuilderSignSync.schedule();

DocBuilderSignSync.unschedule(); stops it.

Instantly (optional), when the service notifies Salesforce:

  1. Create a Salesforce Site and give its guest user access to the Apex class DocBuilderSignWebhookEndpoint only.
  2. In Setup › Custom Settings › Signature Webhook Secret › Manage, add a row named after the provider (for example DropboxSign) with a long random Webhook Secret made of letters and digits.
  3. Ask a developer to create a PlatformEventSubscriberConfig for the trigger DocSignNoticeTrigger, running as an integration user with DocBuilder Admin and access to the provider's credential.
  4. Register https://<site address>/services/apexrest/docbuilder/sign/<ProviderName>?token=<secret> as the callback address in the provider's settings.

Organization limits

In Setup › Custom Settings › DocBuilder Settings › Manage:

SettingEffect
Allowed Email DomainsDocuments can only be emailed to these domains, for example example.com, partner.org. Blank allows any.
Org-Wide Email AddressA verified org-wide address documents are sent from.
Max Email RecipientsMost recipients per document. Default 10.
Max Bulk RecordsMost records per bulk run. Default 2,000.

Automation

In Flow Builder, under the DocBuilder category:

  • Generate Document: template name, record ID, save to the record, optional email to, subject and body.
  • Send Document for Signature: template name, record ID, provider, optional language, subject, message, and signer emails.

Bulk generation for many records runs from Apex; progress shows on the Document Bulk Jobs tab.

Data security

  • Documents are filled with the sender's own access: a field they can't see is not printed.
  • Each generated document keeps a snapshot of the values and rule results it used, visible to its owner and admins.
  • Errors show users a plain message. Technical detail goes to Error Detail, visible only to admins.
  • E-signature notifications are only hints; DocBuilder always asks the service for the real status.

Troubleshooting

SymptomCause and fix
"The template uses a field that does not exist or that you cannot see"Run Check fields. Fix the field name, or give the user access to the field.
"Something went wrong…"Open the Generated Document or Signature Request and read Error Detail.
Only "Send for signature (test)" is offeredNo real provider is active. Set one up and tick Active.
Test connection: "Field DocBuilder_DropboxSign.ApiKey does not exist"Add the ApiKey authentication parameter to the principal.
Test connection: "refused the request (HTTP 401)"The key or sign-in is wrong, or the user lacks the credential permission set.
Signature status never changesSchedule the status check, or click Check status now.
The button is missing on a recordAdd the action to the page layout, and make sure an active template exists for that object.
